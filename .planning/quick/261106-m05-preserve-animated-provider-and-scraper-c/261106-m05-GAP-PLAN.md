# Gap plan: Preserve animated legacy provider-cover downloads

## Finding

The completed metadata-selection correction preserves selected source bytes in
the owned-media catalog. It does not cover the separate legacy provider/scraper
cover downloader: `FSResourcesHandler._store_cover()` calls `store_resource()`
with `cover_size`, where Pillow copies the first frame and serializes a static
PNG/WebP derivative. Therefore a newly downloaded animated source can still be
lost before it becomes a legacy hero or an original cover reference.

ROM 29 is read-only evidence of the consequence, not a recoverable source: its
legacy and owned files are already static PNGs. Missing historical frames must
not be invented.

## Wave 1

1. Make the legacy cover downloader retain animated GIF/WebP bytes at a
   correctly typed cover resource path, while preserving existing static
   big/small derivative behavior and all validation, content-type, and
   publication guarantees.
2. Keep the owned-media catalog bridge source-authoritative and ensure main and
   DLC detail heroes use their exact active owner-scoped candidate endpoints.
3. Align the existing non-image rejection assertion with the already supported
   GIF image contract, then update architecture and quick evidence with the
   read-only ROM 29 limit.

## Verification

- Run only targeted syntax/type/diff checks. Do not create a test file or run a
  test suite before UAT.
- Use the supplied authenticated browser only for read-only main/DLC/ROM 29
  checks. Do not claim animation for the known-static ROM 29 inputs.

## Acceptance

- New GIF/WebP provider/scraper cover downloads do not flatten their animation
  before persistence.
- Static legacy covers and previews remain valid.
- Main and DLC cover ownership stays separate, and absent historical originals
  are clearly documented as irrecoverable.
