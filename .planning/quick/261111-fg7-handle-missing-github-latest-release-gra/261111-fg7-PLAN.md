# Quick Task: Treat the absent first GitHub release as a quiet banner state

## Root cause

`NewVersionBanner` fetches the configured ZockArchive GitHub endpoint ending in
`/releases/latest` after the normal login flow reaches `network-quiesced`. The
GitHub API returns HTTP 404 until the intentionally deferred first release is
published. The component currently parses the error body as a release and then
falls through to `console.error`, turning the expected pre-release condition
into a browser-console failure.

## Scope and guardrails

- The first release remains intentionally unpublished. Do not create a tag,
  GitHub release, image publication, registry login, deployment, or change to
  release/Portainer configuration.
- Do not add, remove, weaken, or execute tests before human acceptance. The
  existing `ProjectBrand.test.ts` is pattern context only and is not modified.
- Keep all non-404 failures observable through the component's existing error
  path. Do not introduce a global fetch wrapper, a snackbar, a new primitive,
  or a second release API path.

## Tasks

1. **Make the expected 404 state silent and safe.** In
   `frontend/src/v2/components/Notifications/NewVersionBanner.vue`, inspect
   `response.ok` before parsing JSON. Per the Phase 43 release decision, an
   HTTP 404 from the canonical `PROJECT_RELEASE_API_URL + "/latest"` means
   that ZockArchive has no published release yet. In that case retain the
   initial hidden state, return without setting a latest tag, and do not call
   `console.error`. For every other non-success status, preserve the existing
   visible diagnostic path by raising an error that the current catch logs.
   Preserve the one-shot `network-quiesced` listener cleanup, semantic-version
   checks, two-hour publication delay, dismissal persistence, and release-link
   behavior. This is a v2 feature composite change, so keep the existing
   typed `<script setup>` and canonical project-config import rather than
   duplicating repository URLs.

2. **Keep the architecture contract accurate.** Update the NewVersionBanner

   latest-release lookup treats a 404 as the normal not-yet-published state,
   stays hidden, and leaves no console error. State that other failures remain
   observable. Do not add phase chronology or duplicate implementation detail.
