# OST subfolder and MP3 download verification

## Result

An isolated, read-only library fixture contained `OST-Demo` with an `OST`
subfolder and two MP3 files. A real desktop browser login started the regular
scan, opened the Windows folder action, selected `OST`, and completed the
subfolder scan. The resulting PC ROM has the `base` component with both
manifest members. A normal authenticated browser request using the UI payload
created a manifest (201) and fetched one selected MP3 member (200).

No product defect was reproduced, so no product source was changed.

## Limitation

The precise mobile fixture flow was not completed: the temporary RQ harness
accepted the scan but dispatched it after the 30-second browser execution
window. This is recorded as open in the UAT report and is not treated as a
passing mobile OST result. Existing mobile scan UI checks remain separate.

## Evidence and cleanup

Screenshots and the detailed report are under the job evidence directory.
The temporary compose project, volumes and fixture files were removed after
the inspection. The NAS and production data were never mounted or changed.
