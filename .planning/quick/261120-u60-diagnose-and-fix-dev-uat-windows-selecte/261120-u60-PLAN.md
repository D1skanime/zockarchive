# Plan

## Scope

Diagnose and correct the Dev UAT recurrence where a selected Windows child scan
does not prevent the parent collection from returning during the next quick
scan. Dev database inspection is read-only. Dev browser verification is
authorized after the diagnosis and correction.

## Steps

1. Read the Dev records for the Tales parent, selected child, source mappings,
   inventory baselines and scan operations before and after the two scans.
2. Trace the selected-child completion and Windows quick-inventory reuse paths
   to identify the persisted state and the exact parent re-admission decision.
3. Document the evidence and root cause before changing production code.
4. Implement the smallest correction that preserves multi-game containers and
   prevents a completed selected child from reintroducing its retired parent.
5. Run the allowed static checks and reproduce the child-then-quick-scan flow
   in Dev at desktop and mobile widths, recording screenshots and results.

## Acceptance

- The report identifies the Dev rows and code paths responsible for parent
  re-admission, including why prior retirement logic did not apply.
- A selected `Tales Of/Tales of Berseria` scan followed by a Windows quick scan
  does not recreate or metadata-match the parent as Tales of War or Total War.
- Multi-game container handling remains unchanged, and the evidence includes
  desktop and mobile Dev browser results.
