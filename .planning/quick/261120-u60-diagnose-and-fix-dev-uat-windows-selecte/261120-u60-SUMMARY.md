# Diagnose Dev UAT Windows selected-subfolder recurrence

## Dev evidence and root cause

The Dev database was queried read-only before the correction. The active Windows
mapping is `pc` (mapping 9). The stale parent was ROM 53 (`pc` / `Tales Of`,
identified as Tales of War), while its selected child was the missing legacy
ROM 36 (`pc-Games/Tales Of` / `Tales of Berseria`) from the former mapping.
The active mapping had a parent quick-inventory baseline but no child baseline.

The selected-child command correctly stored the promotion target
`Tales Of/Tales of Berseria`, but direct mapping discovery initially knew only
the child's name. Consequently it did not recover ROM 36 by its legacy suffix
and the quick-inventory path either reused the stale identity or rejected its
binding before normal file rebuilding. The completion fence from the earlier
fixes was therefore never reached for that child, so the parent stayed eligible
for the next quick scan and was metadata-matched again. This explains why
retiring the parent after completion alone had no effect.

After the repair, the ordinary selected-child scan completed with one scanned,
identified game. ROM 36 is now at `pc/Tales Of`, is no longer missing, and the
active mapping owns `Tales Of` as a collection folder. A subsequent Windows
quick scan completed with two checked entries and no parent ROM 53; the only
Tales result was `Tales of Berseria`.

## Media refresh diagnosis

The read-only Dev inspection of ROM 5500 found IGDB ID 431, an old cover URL,
and no persisted `provider_media` inventory or owned screenshots/artwork.
`prepare_provider_media_refresh` treated that legacy cover fallback as complete
provider media, so `POST /api/roms/5500/media/refresh` returned success without
calling IGDB or publishing screenshots/artwork. The existing correction uses a
persisted provider inventory only when it is genuinely populated; otherwise it
fetches IGDB media and keeps the existing suppression-aware publisher.

After the normal browser refresh, the Dev catalog held 12 screenshots and 12
artworks for ROM 5500 (and its existing cover media). No user suppression or
permission rule was relaxed.

## Implementation

- Carry the explicit collection-promotion path into direct mapping discovery.
- Recover a same-named missing child only for that exact operator-selected
  target, rebuild it under the active mapping, and defer quick-inventory reuse
  until normal identification has done so.
- Allow the checkpoint predicate to recognize the promotion target before the
  narrowed filesystem handler is bound.
- Document the active-mapping recovery and completion-fence behavior.
