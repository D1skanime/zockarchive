# Rebind legacy Windows catalog identity for local soundtrack inventory

## Scope

Investigate the reported Dev Hades scan only through read-only data inspection first.
Trace the active `pc` mapping, the inactive `pc-Games` catalog identity, missing-state
reconciliation, and PC file inventory before changing product code. Preserve the existing
ROM, metadata and media ownership while reconnecting it only when the active mapping and
the missing legacy row unambiguously describe the same Windows game.

## Plan

1. Capture the pre-fix Dev database state for ROM 43, both Windows mappings, its file
   rows and the current scan decision. Record the exact full-scan identity path that marks
   the old row missing.
2. Add a narrowly scoped mapping-identity recovery helper. It must only rebind a unique,
   missing legacy row from an inactive mapping on the same storage root to an active
   mapping identity with the same mapping-relative suffix. The normal scanner must then
   rebuild the ROM's files, including local soundtrack entries.
3. Update backend architecture documentation with the identity-recovery invariant and
   record the root cause and remediation in the Quick summary and project state.
4. Run scoped static verification and the production build without a test suite. In the
   authorized Dev browser, perform a normal full scan, mapping-change regression and quick
   scan, then verify the local OST track, playback and one-member regular download at
   desktop and mobile widths. Save screenshots and append the external inspection report.
