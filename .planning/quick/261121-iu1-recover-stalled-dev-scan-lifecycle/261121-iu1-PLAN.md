# Plan

## Scope

Diagnose the Dev operation stuck in `worker_stop_unconfirmed`, restore it only
through the existing lifecycle and fencing rules, and make the scan UI describe
the actual active blocker and available recovery action.

## Steps

1. Read the affected Dev operation, execution slot, attempt, queue condition,
   worker and request-key records without mutating the database.
2. Trace worker-stop confirmation, reconciler, recovery, operation acceptance,
   and the frontend operation-status rendering to identify why this interrupted
   operation remains active after a worker restart.
3. Record the evidence and root cause before changing runtime code.
4. Implement the smallest lifecycle recovery and UI-state correction that keeps
   write fencing and slot ownership intact.
5. Verify the existing Dev operation through the supported recovery path, then
   start a normal scan and a ROM metadata refresh from the browser at desktop
   and mobile widths. Record screenshots and outcomes.

## Acceptance

- No lock is deleted or bypassed, and the active slot changes only through the
  durable operation lifecycle.
- An interrupted `worker_stop_unconfirmed` operation is either safely resumed
  or terminally reconciled, releasing the slot only after its ownership check.
- The scan view shows the active blocked operation and a concrete recovery
  action rather than stale completion data and a generic start failure.
- A subsequent scan start and ROM metadata refresh work after the Dev worker
  restart, with desktop and mobile browser evidence.
