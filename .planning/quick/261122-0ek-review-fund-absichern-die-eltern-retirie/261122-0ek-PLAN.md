# Plan

1. Extract the completion checkpoint into a focused helper that preserves an
   in-flight scan exception while still committing a selected child retirement.
2. Enclose every post-`scan_rom` processing step in that checkpoint and bind
   the persisted child immediately after `merge_scan_rom`.
3. Update backend architecture documentation, lint/typecheck the touched code,
   and inspect the corrected scan flow in the running browser without adding a
   new test suite.

## Acceptance criteria

- A generic exception after `scan_rom` cannot skip the selected-child
  completion checkpoint once the catalog child exists.
- A checkpoint failure does not mask an earlier scan error.
- Normal completion remains exactly once, including hash and metadata-only
  short circuits.
